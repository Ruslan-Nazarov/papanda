# Автоматизация публикации (Publish Workflow)

Выполняй эти шаги строго по порядку:

### 1. Предварительная проверка (Безопасность)
- Проверь `git status` и список измененных файлов.
- Убедись, что файлы базы данных (`.db`, `.sqlite`), приватные ключи, и другие секреты не попадут в коммит. Если они не в `.gitignore` или добавлены случайно — предупреди пользователя.

### 2. Сбор списка изменений (Changelog)
- Проанализируй изменения (`git diff` или список файлов).
- Самостоятельно напиши красивый список изменений.
- **ВАЖНОЕ ПРАВИЛО БЕЗОПАСНОСТИ**: Список изменений всегда составляется строго в продуктовом контексте для конечных пользователей. Запрещается упоминать внутренние технические детали реализации (названия файлов, классов, методов, модулей, промптов), чтобы не раскрывать чувствительную структуру кода.
- Добавь его в файл `CHANGELOG.md` в начало списка. В качестве версии временно укажи `[ОЖИДАЕТСЯ ВЕРСИЯ]`.
- **Покажи пользователю составленный список изменений (логи).**
- **Попроси пользователя проверить логи и дополнить их, если это необходимо.**
- **Остановись и дождись подтверждения от пользователя.**

### 3. Обновление версии во всех файлах проекта
- Спроси пользователя: *«Какую версию ставим?»* (посмотри текущую в `CHANGELOG.md` или `fastapi_app/templates/index.html`, чтобы подсказать пользователю).
- **Остановись и дождись ответа пользователя.**
- Получив ответ, ОБЯЗАТЕЛЬНО проверь и обнови номер версии (а также дату последнего обновления `last update`) во ВСЕХ следующих точках проекта:
  - `fastapi_app/templates/index.html` (в футере номер версии и дата `last update`)
  - `CHANGELOG.md` (замени заголовок `[ОЖИДАЕТСЯ ВЕРСИЯ]`)
  - `fastapi_app/main.py` (в параметре `version="..."` конструктора FastAPI)

### 4. Деплой (Отправка на сервер)
- Выполни `git add .`
- Сгенерируй профессиональное сообщение для коммита на основе списка изменений.
- Выполни `git commit -m "..."`.
- Выполни `git push`.
- Сообщи пользователю об успешной публикации.
