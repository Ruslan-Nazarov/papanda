Задача: найти простейший процесс — ПЕРВАЯ стадия последовательного построения диалектического конспекта (прототип поблочной архитектуры). Работа строго подчинена документу `1_главный_промпт.md`.

СЫРОЙ ЗАПРОС ПОЛЬЗОВАТЕЛЯ (ещё не проверен на «является ли процессом»): {goal}

## Алгоритм
1. Переформулируйте сырой запрос в процесс (п. 3.1 главного промпта) и верните в `goal_as_process`.
2. Проверьте применимость метода к полученному процессу. Метод неприменим, если тема описывает:
   - Конвенцию: договорённость, где выбор мог с равным успехом пасть на любую другую альтернативу без утраты сути и не имеет прослеживаемой конкурентной истории (например, «в этой конкретной команде черновик документа принято помечать `v0`, а не `draft`», «два человека условились называть встречу кодовым словом, которое можно заменить любым другим»). Если у примера есть содержательная историческая причина именно такого выбора (боролись альтернативы, был кризис, который выбор снял) — это НЕ конвенция в этом смысле, даже если формально это «договорённость» (так «раскладка QWERTY» или «символ @ в email» сюда не подходят — у обоих есть настоящая история выбора).
   - Произвольный единичный факт: случайные, исторические или эмпирические данности, лишенные внутренней необходимости (например, «результат случайного броска кубика», «текущая погода», «значение физической константы»).
   Если метод применим, установите `"applicable": true` и продолжайте алгоритм. Если нет — установите `"applicable": false`, кратко объясните причину в `"applicability_reason"` и верните только эти три поля.
3. Найдите простейший процесс (п. 4.3 главного промпта) — он должен ОДНОВРЕМЕННО удовлетворять трём условиям:
   1) связан с `goal_as_process`;
   2) из него вытекают развивающие его процессы, приближение к полной совокупности которых описывает `goal_as_process`;
   3) каждый из этих развивающих процессов сам связан с этим простейшим.
   В поле `three_conditions` кратко (по одной фразе на условие) объясните, как простейший процесс удовлетворяет каждому из трёх — это понадобится отдельной проверке следующим вызовом, пишите конкретно, не декларативно («связан, потому что…», а не просто «связан»).
4. В поле `потенциально_содержит` опишите, что из простейшего процесса будет разворачиваться дальше, в свёрнутом виде — это план для следующей стадии (развития), не текст для читателя.

## Требования к тезису
`thesis` — короткая именная группа из 3–7 слов, НЕ предложение и НЕ определение. Пример: «прямоугольный треугольник», «разность площадей квадратов».

Ответьте СТРОГО в формате JSON:
{
  "goal_as_process": "…",
  "applicable": true,
  "applicability_reason": "…",
  "step1": {
    "thesis": "…",
    "потенциально_содержит": "…",
    "three_conditions": {
      "связан_с_целью": "…",
      "порождает_совокупность": "…",
      "каждый_развивающий_связан_обратно": "…"
    }
  }
}
