# Papanda / Conspect 0.12.4

Редактор конспектов: ручной режим по умолчанию, дополнительная ИИ-генерация,
история, формулы, категории и публичные ссылки. Backend: FastAPI + SQLAlchemy +
SQLite; frontend: браузерные ES-модули и TipTap.

## Локальный запуск

Нужны **Python 3.12** и **Node.js >=22.12** для сборки интерфейса и тестов.
Команды выполняются из корня этого репозитория.

### Windows / PowerShell

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --require-hashes -r requirements-dev.txt
# Если .env ещё нет: Copy-Item .env.example .env
npm ci
npm run build
.\.venv\Scripts\python.exe run.py
```

Если Python отсутствует в `py`, вместо него укажите путь к установленному
Python 3.12. Существующий `.env` сохраняйте. `run.bat` использует `.venv`.

### Linux

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install --require-hashes -r requirements-dev.txt
# Если .env ещё нет: cp .env.example .env
npm ci
npm run build
.venv/bin/python run.py
```

Адрес: http://127.0.0.1:8080. `HOST`, `PORT`, `UVICORN_RELOAD` управляют запуском.
В production устанавливайте `requirements.txt` вместо `requirements-dev.txt`;
reload выключайте. Для demo — один worker (проверяется блокировкой при старте).
Квоты хранятся в SQLite и переживают перезапуск. При прямом запуске Uvicorn
используйте `--no-proxy-headers`, чтобы приложение само проверяло доверенный прокси.
Для ручного редактора API-ключи не нужны. Для ИИ настройте используемый провайдер
в `.env`; доступность модели зависит от провайдера и аккаунта.

## Данные и режимы

### Диалектическое изложение статьи

В «Источниках блока» у статьи или книги есть маленькая кнопка ✦ рядом с
редактированием и удалением. Она загружает текст публичной HTML-страницы или PDF
и показывает потоковый ответ с формулами в отдельном окне. Якорь ссылки
ограничивает изложение соответствующим разделом. Название источника передаётся
ИИ вместе с текстом. Явное указание «Разделы 3.1–3.3» в заметке
тоже учитывается. В PDF поддерживаются страницы, например `#page=12` или
«стр. 12–16». Не найденный раздел вызывает ошибку, без подмены всей книгой.
Ответ можно скопировать либо сохранить у источника через «Сохранить» и
подтверждение. Сохранённое изложение открывается без нового ИИ-запроса;
изменение ссылки, названия или заметки сбрасывает старое изложение.
Промпт объединяет главный
промпт, восстановление, анализ статей и `prompts/изложение_статьи.md`.
Если страница недоступна, используется прикреплённая цитата или заметка с явным
указанием, что разобран только этот фрагмент. Без текста запрос завершается
ошибкой; материал длиннее 100 000 символов не обрезается и не отправляется ИИ.
Закрытие окна отменяет запрос. Запрос и ответ записываются в общий дневник ИИ.

### Происхождение чисел в формулах

Нажатие на число показывает цепочку «правило → раскрытие по координатам →
исходная ячейка» или вычисление, из которого собран элемент итоговой матрицы.
Каждый шаг позволяет перейти к исходной формуле и вернуться к выбранному числу.
Жёлтый фон с пунктирной рамкой обозначает совпадение чисел внутри блока;
сплошное бирюзовое подчёркивание — связь с источником. Оба признака могут
отображаться одновременно. В подсказке есть независимые переключатели двух
слоёв; выбор сохраняется до перезагрузки страницы.
Связи строятся в браузере без ИИ и пересчитываются при изменении конспекта;
исходный текст формул и сохраняемый HTML не меняются.

Поддерживаются численные скаляры, векторы, матрицы, сложение и вычитание,
скалярное и матричное умножение, дроби, степени, транспонирование,
покоординатные функции (включая `max`, `min`, ReLU, `tanh`) и конечные суммы
с известными целыми границами. Нумерация с нуля определяется по координатным
формулам и распространяется на связанные величины; иначе используется отсчёт
с единицы. Совпадение чисел проверяет структурную связь, но не выбирает источник.
При нескольких возможных связях показывается неоднозначность. Неподдерживаемая
запись не получает выдуманного источника.

Разбор ограничен 12 000 символами на выражение, 512 элементами на массив
и ближайшими 24 шагами происхождения; продолжить цепочку можно из исходной
формулы. Интегралы, произвольные преобразования выражений и восстановление
отсутствующих определений не поддерживаются.

### Papanda Personal для Windows

Личная сборка выпускается отдельно от сайта из этого же репозитория. Она не
содержит `.env`, ключей автора, его баз и примеров конспектов. Публикация в
авторскую библиотеку отключена на сервере и скрыта в интерфейсе. Ручная работа
доступна без ключа; свой ключ и модель пользователь добавляет в «Настройки ИИ».
Настройки применяются после закрытия окна запуска и повторного запуска программы.

Скачать готовую программу: [Papanda Personal — Releases](https://github.com/Ruslan-Nazarov/papanda/releases).
В разделе **Assets** выберите `Papanda-Personal-<версия>-Windows-x64.zip`.
Нужно распаковать его целиком и запустить `Papanda.exe`. Python и Node на компьютере
пользователя не нужны. Данные хранятся отдельно: `%LOCALAPPDATA%/Papanda/Personal`.
Для резервной копии закройте приложение и скопируйте эту папку целиком; для
восстановления верните копию в ту же папку при закрытом приложении. `settings.env`
содержит ключи пользователя и не предназначен для отправки другим людям.

Сборка на Windows после установки runtime-зависимостей и `npm ci`:

```powershell
.\.venv\Scripts\python.exe -m pip install --target .cache/personal-build-tools pyinstaller==6.22.3
npm run build
.\.venv\Scripts\python.exe scripts/build_personal.py --tools .cache/personal-build-tools
```

Workflow **Build Papanda Personal for Windows** запускается через **Actions → Run workflow**.
По умолчанию он собирает программу, проверяет запуск и сохранение после перезапуска,
а затем публикует ZIP с SHA256 в GitHub Releases с тегом `personal-v<версия>`.
Снимите флажок **publish**, чтобы получить только artifact без публикации.
Публикация также запускается при отправке тега `personal-v<версия>`; версия тега
должна совпадать с `fastapi_app/version.py`. Уже существующий релиз не заменяется:
для следующего выпуска увеличьте версию приложения. Локальный архив сборки находится
в `output/personal/`. Этот workflow не запускает деплой сайта и не использует
ключи ИИ или доступ к серверу.
Для запуска без упаковки: `.\.venv\Scripts\python.exe run_personal.py`.
Сборщик автоматически проверяет ZIP, включая скомпилированный Python, на наличие
ключей из локального `.env`, типичных секретов, локальных путей автора и файлов
с данными. Публичные контакты автора сохранены для обратной связи. Аналитика
сайта в личной версии не загружается; браузеру разрешены только локальные подключения.

### Хранение

При входе на главную страницу открывается новый пустой конспект.
Сохранённые конспекты открываются через меню или прямую ссылку `/?note=<id>`.
Обычное открытие и сохранение не меняют адрес главной страницы, поэтому
повторный вход на `/` также начинает с пустого конспекта. Прямая ссылка
`/?note=<id>` по-прежнему открывает указанный конспект.

К запросу можно прикрепить один DOCX или TXT в UTF-8 через «Прикрепить документ»
внутри блока постановки задачи. Максимум — 2 МиБ и 50 000 символов извлечённого текста.
Текст можно просмотреть, заменить или удалить; он сохраняется у блока цели,
в версиях и копиях конспекта. Сохраняется имя и извлечённый текст, без исходного
бинарного файла. Материал передаётся при полной генерации и перегенерации шага;
публичные ссылки и публикации исходное вложение не раскрывают.

В `dialectic_v3` документ расположен до меняющихся заданий этапов для повторного
использования кэша входа у поддерживающего провайдера. В отчёте генерации
`cached_input_tokens` показывает сообщённое провайдером число закэшированных
входных токенов; `null` означает, что данных нет. Попадание в кэш зависит от
провайдера и модели. Материал передаётся полностью, без автоматического сокращения.

- `DEMO_MODE=false`: личная БД `data/db/papanda.db`; запросы разрешены только
  с loopback и локальным Host, без прокси.
- `DEMO_MODE=true`: отдельная БД на серверную сессию в `data/demo/`, случайная
  cookie проверяется в реестре и продлевается на 30 дней при работе. Автоматическое
  удаление данных выключено. Публичные ссылки работают между
  сессиями через реестр токенов; личные стикеры и служебные поля не публикуются.
- `DATABASE_URL` переопределяет личную БД. На данном этапе проверяется SQLite.
  Для нестандартных путей задавайте `DB_DIR` и `DEMO_DIR` явно: изменение только
  `DATA_DIR` не пересчитывает остальные значения Settings.

Удалённый конспект попадает в отдельную «Корзину». Его можно восстановить в течение
30 дней; затем он удаляется окончательно. Очистка выполняется при открытии корзины
и фоновым заданием раз в час, в том числе для неактивных демосессий.

Настройка HTTPS/proxy, сессий, квот, импорта и GigaChat CA описана в
[решении R2](docs/access-and-import-boundaries.md). Прежний UUID-cookie восстанавливает
доступ к соответствующей старой базе через её безопасную копию; оригинал сохраняется.
Имя новой базы или произвольный идентификатор не дают доступ к чужой сессии.
Многопользовательский сервис с аккаунтами пока не поддерживается.
Полный статус этапов — `docs/refactoring-progress.md`.

## Теги словаря

В словаре конспекта статье можно назначить несколько тегов. Цветные кнопки
над списком фильтруют статьи; рядом с названием показано их количество.
Есть отдельный фильтр «Без тегов», а поиск находит и названия тегов.
В графе фильтр отбирает центральные понятия; их связи остаются доступны.
Переход к связанному понятию вне фильтра сбрасывает фильтр.

В редакторе статьи теги выбираются кнопками; здесь же можно создать новый
тег. Назначения применяются по кнопке «Сохранить», отмена оставляет их
прежними. «Настройки тегов» в окне словаря позволяют создавать, переименовывать,
менять цвет и удалять теги. Эти настройки общие для статей текущего конспекта.
Удаление тега снимает его со статей и сохраняет сами статьи. Изменения словаря
сохраняются вместе с конспектом, его версиями и копиями.

Миграция базы 009 один раз распределяет существующие статьи по начальным
категориям, предварительно сохраняя резервную копию базы. Дальнейшие назначения
можно свободно менять: повторный запуск их не пересматривает.

## Форматирование текста

В редакторе «Размер текста» задаёт размер от 12 до 32 пикселей; «Авто»
возвращает размер по умолчанию. Размер сохраняется в конспекте и публичной
версии. Кнопка с метлой снимает текстовое оформление, заголовки и списки.
Оба действия применяются к выделенному фрагменту, а без выделения — ко всему
тексту блока. Изменения можно отменить обычным Ctrl+Z.

## Дневник запросов к ИИ

Кнопка «Дневник ИИ» рядом с сохранением открывает запросы только текущего
конспекта. Записи сгруппированы по дням, раскрываются для чтения ответа;
доступны поиск по тексту и фильтр по результату. У нового конспекта дневник
пустой. Просмотр дневника не создаёт и не изменяет конспект.

Время показывается в часовом поясе устройства, указанном в окне дневника.
Старые записи содержат время сохранения ответа: UTC из SQLite явно
передаётся с часовым поясом и преобразуется браузером в местное время.
У новых запросов также сохраняются начало и длительность. При переходе
к другому конспекту запоздавший ответ остаётся в дневнике исходного конспекта.

## Архив ошибочных вариантов

В текстовом редакторе «Переписать заново» переносит текущий текст в
«Предыдущие варианты» под полем и освобождает поле для новой записи. Карточки
раскрываются; к каждой можно добавить причину отказа. Сразу после переноса
доступна отмена. Новый текст и архив сохраняются вместе по ОК; закрытие
редактора без ОК отменяет эти изменения. Архив сохраняется в конспекте, его
копиях и истории. При полной генерации и продолжении шага ИИ получает
архив отдельно от актуального текста как ошибочные варианты; при генерации
одного шага архив последующих шагов не передаётся. Публичные версии архив
не содержат.

## Авторская библиотека

Выбранные автором конспекты входят в Git-деплой приложения через
`fastapi_app/data/library_notes.json`. Библиотека открывает их в обычном
приложении со всеми инструментами редактора, стикерами, словарём, связями,
материалами, метками, пояснениями и предыдущими вариантами блоков.

В личном приложении кнопка «Публикация» включает или исключает текущий
конспект из файла следующего деплоя. После выбора файл нужно закоммитить и
отправить в GitHub вместе с кодом сайта. Отдельная отправка снимка на сервер
для этого механизма не требуется.

Постоянная ссылка имеет форму `/?conspect=ecg-final&lang=en`. Языковой флаг
определяет язык интерфейса и содержимого. Переводы хранятся в одной логической
записи конспекта; переключение языка сохраняет выбранный конспект. Сейчас
опубликованы два примера ЭКГ с русским и английским текстом.

В деморежиме посетитель работает со своими обычными экземплярами конспектов.
Его сохранения и действия редактора не меняют авторский файл в Git или
конспекты других посетителей. Исходная запись автора остаётся локальной;
публикуются только явно выбранные конспекты.

## Проверки приложения

Последний обзор рабочей копии, исправления и предложения перед следующим
этапом: [аудит 20.10.2026](docs/audit-2026-10-20.md).

```powershell
npm ci
npm run build
.\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider
.\.venv\Scripts\python.exe -m coverage run -m pytest -q -p no:cacheprovider
.\.venv\Scripts\python.exe -m coverage report
npm run lint
npm run check:types
npm run check:js
npm test
npm run test:browser
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path (Get-Location).Path '.cache/playwright-browsers'
npx playwright install firefox webkit
npm run test:cross-browser
```

На Linux используйте `.venv/bin/python`. `npm ci` устанавливает Puppeteer и
совместимый Chromium; Linux также требует системные библиотеки Chromium.
Логические тесты `npm test` и проверка синтаксиса не требуют браузера.
Для установки только пакетов: `npm ci --ignore-scripts`, затем при необходимости
`npx puppeteer browsers install chrome`.
Для межбраузерной проверки на Linux: `PLAYWRIGHT_BROWSERS_PATH="$PWD/.cache/playwright-browsers" npx playwright install --with-deps firefox webkit`,
затем `npm run test:cross-browser`. Эти проверки используют временные данные и
подставные ответы ИИ. WebKit не заменяет Safari на настоящем iPhone.

Живые проверки ИИ запускаются отдельно, осознанно используя настроенные ключи:
`python scripts/verify_live_ai.py --live --pipeline`. Без `--live` запросов нет;
ответы и метрики пишутся в `.cache/live-acceptance`, пользовательская БД не меняется.
Для отдельных сценариев есть `--only calculation incorrect_calculation`.

Python-тесты используют временные каталоги и отключённые ключи ИИ. Фикстура
`file_client` запускает настоящий lifespan и get_db с файловой SQLite.
JS unit-тесты загружают реальные тела модулей с подменёнными импортами; browser-тесты
проверяют DOM и пользовательские сценарии на отдельном сервере с временной БД:
ручной ввод, save/reload, версии, sharing, формулы, рисунки, графики, клавиатура,
узкий экран и генерация через mock SSE. Внешние запросы блокируются.

После изменения JS/CSS выполняйте `npm run build` и обновляйте страницу.
Сборка пишет файлы с хешами в игнорируемый `fastapi_app/static/dist` и manifest
для шаблонов. Node не нужен работающему Python-серверу после сборки.
Подробнее: [архитектура редактора](docs/editor-architecture.md).

Регрессии R1 выполняются без `xfail` и `todo`: SQLite FK/история, гонки сохранения,
DOM-инъекции, статусы ИИ-блоков и сохранение рисунков.

В HTML блоков поддерживаются встроенные PNG/JPEG/WebP (base64), не более 2 МиБ
на изображение. Проверяются MIME, сигнатура файла и размер; это не полная проверка
декодирования изображения. SVG и внешние URL изображений не принимаются при записи;
опасные атрибуты удаляются. Ошибка изображения возвращает HTTP 422 до изменения БД.

## Обновление зависимостей

`requirements.in` — прямые runtime-версии; `requirements-dev.in` добавляет
тестовые инструменты. `requirements*.txt` — сгенерированные универсальные locks
для Python 3.12, включая транзитивные версии, условия платформ и хеши.

После изменения `.in`:

```powershell
.\.venv\Scripts\python.exe scripts\lock_dependencies.py
.\.venv\Scripts\python.exe -m pip install --require-hashes -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pip check
```

Генератор использует закреплённый `uv==0.11.15` из dev-зависимостей. Dev-lock
ограничен runtime-lock, чтобы общие версии совпадали. Для обновления транзитивного
пакета используйте `uv pip compile --upgrade-package <name>` с остальными флагами
из заголовка lock, затем пересоздайте dev-lock. JS-зависимости редактируются через
package.json/package-lock.json; библиотеки, иконки и шрифты собираются локально.
После обновления выполняйте `npm run build`, тесты,
`python scripts/audit_dependencies.py` (все платформенные ветви) и `npm audit`.

## Резервная копия SQLite

```powershell
.\.venv\Scripts\python.exe scripts\backup_db.py data\db\papanda.db backups\before-migration.db
```

Используется SQLite backup API: консистентный снимок, включая committed WAL,
проверка целостности и пробное восстановление в памяти. Существующий файл назначения
не перезаписывается. Для восстановления остановите приложение, восстановите снимок
в новый каталог и запустите приложение с `DATABASE_URL`, указывающим на этот файл.
Не заменяйте активную БД с открытыми соединениями и WAL. Backup содержит личные
данные и требует тех же ограничений доступа, что исходная БД.

На каждом соединении включены SQLite foreign keys. При первом открытии БД
нарушенные ссылки блокируют её использование. Для восстановления создайте копию:

```powershell
.\.venv\Scripts\python.exe scripts\repair_db_copy.py data\db\papanda.db backups\repaired.db
```

Исходная БД остаётся неизменной. В копии повреждённые версии/связи удаляются из
рабочих таблиц, несуществующая категория сбрасывается; исходные строки сохраняются
в `_integrity_quarantine`. Неизвестные связи приводят к откату ремонта. Перед
подключением копии проверьте её содержимое. Уже ошибочно привязанную к существующему
ID историю автоматически распознать нельзя — потребуется сверка с резервными копиями.

## Порядок изменений

Статус этапов: [docs/refactoring-progress.md](docs/refactoring-progress.md).
PR и push в main запускают проверки, сборку и аудит зависимостей. После успешных
проверок push в main автоматически обновляет существующий `/root/papanda`, его
`venv` и сервис `papanda`; собранный интерфейс доставляется из CI.
Переменная `PAPANDA_RELEASES_READY` не требуется. Ручной запуск workflow на main
также выполняет деплой: [инструкция выпуска и восстановления](docs/deployment.md).
Авторские методологические файлы `prompts/*.md` изменяются только по отдельному
конкретному поручению. Изменения кода и исправления контрактов делаются отдельно.

## Контракты и сопровождение

- SQLite `user_version=3`; формат документа и блока `schema_version=1`.
  Миграция сохраняет общие стикеры в заметке и версиях; старый `sticker_text`
  переносится в массив. Перед изменением существующей БД создаётся снимок.
- Конкурирующие сохранения проверяют `revision`; конфликт возвращает 409.
- Общие стикеры входят в save/history, JSON примеров, Markdown и TXT.
  Публичное представление исключает личные стикеры.
- Активные провайдеры: Groq, Cerebras, Google, OpenRouter, GigaChat.
  Неиспользуемые адаптеры Hugging Face и SambaNova удалены. Режим Auto
  использует доступные настроенные провайдеры; модели задаются через Settings/.env.
  Качество и доступность реальных моделей проверяются отдельно.
- Обычные маршруты ограничены 120 запросами/минуту на IP и endpoint;
  AI-маршруты имеют собственные более строгие лимиты и сохраняемые квоты.
- `/guide`, `/pinned/active`, `/search/notes`, `/{id}/status`, `/{id}/unpin`
  под `/api/dialectics` помечены deprecated. Текущий UI их не использует;
  они сохранены для неизвестных внешних клиентов. Используйте список с
  фильтрами и PATCH документа с revision. Методика доступна в меню приложения.
- `run.py` выдаёт JSON-события без текста запросов, ответов, секретов и URL-токенов.
  `/health` сообщает версию, SHA релиза, готовность и агрегаты генерации.
