# ADR 004 — миграции и выпуск

Принято: 24.09.2026, R6.

**Контекст.** Обновление активного checkout и окружения не обеспечивало
соответствие проверенному SHA и восстановление после неудачной миграции.

**Решение.** CI собирает архив SHA + manifest с хешами; сервер создаёт отдельный
release и venv. На копии БД проверяются миграция, запуск и локальные assets.
После остановки сервиса создаётся окончательный снимок, мигрируются данные
и атомарно переключается current.json. API открывается только после проверки
SHA. Файловая блокировка и concurrency GitHub предотвращают одновременный deploy.

**Следствия.** До открытия API ошибка вызывает возврат к прежнему release,
его venv и снимку данных. Поздний ручной откат требует сохранения новых записей
и решения об их переносе. Down-миграций нет. Неисправность диска, аварийное
завершение процесса и неудача самого восстановления требуют вмешательства;
сервис остаётся закрытым, а снимки сохраняются. Первый перенос старого сервера
в новую структуру выполняется отдельно по runbook.
